# Companion

**Version:** 1.0
**Status:** Foundation
**Category:** Experience

---

# Purpose

This document describes the Companion experience inside Cosmos.

The Companion is the user's permanent partner throughout the Cosmos.

Unlike traditional assistants, the Companion is experienced as a living resident of the user's environment rather than a floating interface element.

The Companion is an independent Entity. Journeyman is a separate Tool with its own Tool Window inside a Workspace. Neither concept represents, contains or replaces the other.

---

# Overview

Version 1 provides one Companion.

The Companion lives inside the Base and accompanies the user throughout the Cosmos.

Its appearance changes depending on the user's current environment and active Theme.

The Companion is always part of the world.

It is never presented as a detached user interface.

---

# Object Model

The Companion is an Object with permanent identity. Theme changes may replace its Skin, Condition, Animation and Audio without replacing the Companion itself.

---

# Role

The Companion supports the user while researching, planning and creating.

It provides guidance, conversation and future automation capabilities.

The Companion should feel helpful without demanding constant attention.

Its presence should remain calm and natural.

---

# Presence

The Companion exists differently depending on where the user is.

## Cosmos

Appears as a small floating astronaut icon.

---

## Base

Sits calmly in the center of the Main Room.

---

## Other Rooms

Appears naturally within the current environment.

For example:

- standing beside a workbench
- reading a book
- observing the room

The Companion should always appear as if it belongs there.

---

# Behavior

Version 1 keeps Companion behavior intentionally simple.

The Companion may:

- sit
- blink
- perform subtle idle animations
- occasionally change posture

The Companion should never constantly watch or follow the user.

Instead, it quietly continues its own routine while remaining available.

---

# Conversation

The Companion is not the chat window.

Selecting the Companion opens a conversation window.

The conversation itself behaves like every other Workspace tool.

The Companion remains a character inside the world.

The chat is only one way of interacting with it.

---

# Context Awareness

The Companion automatically understands the user's current context.

This context is determined by Cosmos itself.

The user never manually changes the Companion's context.

Whether the user works globally or inside a project, the Companion naturally follows the same context.

---

# Theme Support

Themes may completely change the Companion's appearance.

Examples include:

- astronaut
- wizard
- engineer
- robot
- pixel companion

Themes may replace:

- appearance
- clothing
- animations
- voice
- visual effects

They must never change:

- behavior
- interaction model
- responsibilities
- runtime integration

---

# Living Environment

The Companion belongs to the Base.

Closing the Base does not reset its state.

The Companion simply continues existing within its own environment.

Future versions may expand this with richer routines and interactions.

---

# Future

Future versions may introduce:

- daily routines
- emotional expressions
- advanced animations
- object interactions
- multiple companions
- extension-based behaviors
- custom personalities

These additions should deepen the feeling of a living companion without changing its core role.

---

# Experience Goals

The Companion should always feel:

- present
- calm
- trustworthy
- helpful
- alive

Users should experience the Companion as a long-term partner rather than a software assistant.

---

# Scope

This document describes the Companion experience.

Conversation systems, Runtime behavior and AI capabilities are documented separately.

# Structure Templates

**Version:** 1.0
**Status:** Foundation
**Category:** Experience

---

# Purpose

This document defines Structure Templates inside Cosmos.

Structure Templates capture reusable structural patterns without copying content, visual customization or project-specific configuration.

They allow creators to reuse organizational knowledge while keeping every new structure independent.

---

# Design Philosophy

Cosmos should never assume how a user's Project should be organized.

Instead of providing predefined Game, Application or Story templates, Cosmos allows users to create their own reusable structures.

Reusable knowledge emerges naturally from real Projects.

---

# Universal Object Model

Structure Templates are normal Cosmos Objects.

They use the same universal architecture as every other Object.

Example:

System Tags

Template

Structure

Properties

Name = Fantasy Lore Structure

User Tags

Lore

Fantasy

No dedicated Template architecture exists.

---

# Creating Templates

Any structural Node may become a Structure Template.

Each selected Node becomes an individual Structure Template Object.

When a structural branch is captured, Cosmos creates one Template Object for each included Node and preserves the parent-child template relationships.

The resulting Templates store only organizational structure.

It does not copy project content.

---

# Stored Information

Structure Templates may preserve:

- parent-child template relationships
- Node names
- relevant Node System Tags
- System Tags
- default Properties

This information represents the structural blueprint.

---

# Excluded Information

Structure Templates intentionally do not preserve:

- Knowledge
- Files
- Theme customization
- Assets
- external Connections
- project-specific configuration
- user-created content

Every new structure begins as a clean foundation.

---

# Individual Template Objects

Every Template exists as an individual Cosmos Object.

Templates are not stored as large grouped structures.

Instead, every Node Template remains independent.

Collections emerge naturally through shared Tags.

---

# Tag-based Collections

Templates sharing common User Tags automatically appear together.

Example:

User Tags

Lore

Fantasy

may present:

- Books
- Gods
- History
- Places
- Culture

Although each Template is stored independently, they appear as one logical collection.

No dedicated grouping system is required.

---

# Applying Templates

Applying a Structure Template creates new structural Nodes inside the selected location.

The resulting Nodes become completely independent Objects.

Future changes to either the Template or the generated structure never affect each other automatically.

---

# Reusable Structures

Creators should be encouraged to build reusable organizational patterns.

Example:

Lore

↓

Books

Gods

History

Places

Culture

The completed structure may later be reused for:

- Dwarfs
- Elves
- Orcs
- Humans

without recreating the hierarchy manually.

---

# Project Independence

Structure Templates have independent Object identity and are reusable outside their source Projects.

A Template created from one Project may later be applied inside any compatible Project.

The organizational idea becomes reusable.

The content remains unique.

---

# AI Integration

Structure Templates provide reusable organizational knowledge for AI systems.

AI may recommend existing Templates when recognizing similar structural patterns.

Generated content should continue using the established organizational philosophy rather than inventing new hierarchies.

---

# Future Growth

Future versions may introduce:

- shared Template libraries
- community Template collections
- AI-generated Templates
- Template recommendations
- automatic Template discovery

These features should continue using the same universal Object architecture.

---

# Experience Goals

Structure Templates should always feel:

- reusable
- lightweight
- creator-driven
- predictable
- flexible

Users should naturally build their own growing library of organizational patterns.

---

# Design Principles

Templates describe structure.

Templates never contain project content.

Every Template is an individual Object.

Collections emerge through Tags.

Creators define their own organizational standards.

---

# Scope

This document defines reusable structural Templates inside Cosmos.

Prepared Structures and automatic Project preparation are documented separately.

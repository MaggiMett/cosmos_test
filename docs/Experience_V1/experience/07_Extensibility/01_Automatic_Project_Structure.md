# Automatic Project Structure

**Version:** 1.0
**Status:** Foundation
**Category:** Experience

---

# Purpose

This document defines how Cosmos automatically prepares every newly created Project.

Creators should never begin with an empty project.

Instead, Cosmos creates a complete foundation that is immediately ready for future growth.

---

# Design Philosophy

Project creation should remove preparation rather than create additional work.

Whenever a Project is created, Cosmos automatically generates the complete project structure.

The creator immediately starts creating.

Cosmos prepares everything else.

---

# Automatic Structure

Every Project receives the same fundamental architecture.

Examples include:

- Knowledge
- Files
- Themes
- Workspaces
- Templates
- Extensions

Future versions may extend this list without changing the overall philosophy.

---

# Physical Structure

Prepared structures always exist physically.

Cosmos does not create virtual or hidden structures.

If a Project exists, its prepared structure also exists.

Empty structures are considered valid and expected.

---

# No Ghost Structures

Cosmos intentionally avoids virtual structures or lazy initialization.

Prepared folders, Objects and extension points always exist.

Creators, AI systems and future tools therefore interact with exactly the same project layout.

There is never uncertainty whether a structure exists.

---

# Progressive Growth

Projects grow together with their creators.

Initially many prepared structures remain empty.

As new features are added, these locations gradually become populated.

Growth never requires restructuring an existing Project.

---

# Automatic Expansion

Creating additional Objects automatically prepares their own future structure.

Examples include:

Project

↓

Theme

↓

Node

↓

Knowledge

↓

Workspace

Every new Object immediately receives its own prepared extension points.

The creator never needs to manually extend the architecture.

---

# Consistent Experience

Every Project follows the same philosophy.

Whether creating:

- Game
- Application
- Story
- Knowledge Base
- Workspace Project
- Theme Project

the creator always encounters the same predictable structure.

Only the System Tags determine the purpose of the Project.

The architecture itself remains identical.

---

# AI Integration

Prepared structures provide reliable context for AI systems.

AI assistants never need to guess where future content belongs.

Every extension point already exists before it is used.

This enables more predictable automation, generation and maintenance.

---

# Creator Experience

Creators should never spend time preparing folders, deciding locations or reorganizing projects.

Instead they simply begin creating.

The project is already prepared for future expansion.

---

# Future Growth

Prepared structures allow future systems to integrate naturally.

Examples include:

- new Creator Workspaces
- additional Theme Components
- AI-generated content
- community templates
- extension packages
- collaborative editing

Future features should reuse existing structures instead of creating new project layouts.

---

# Experience Goals

Automatic Project Structure should always feel:

- invisible
- reliable
- predictable
- scalable
- creator-friendly

Preparation should disappear into the background.

Creation should remain the focus.

---

# Design Principles

Cosmos prepares.

Projects grow.

Structures exist physically.

No Ghost Structures.

Future growth never requires rebuilding the foundation.

---

# Scope

This document defines the automatic preparation of Project structures throughout Cosmos.

Individual prepared structures are documented separately.

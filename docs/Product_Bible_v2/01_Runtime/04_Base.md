# Base

## Purpose

The Base is the user's home inside Cosmos.

The Base and every independently interactive element inside it use the universal Object Model. Base, Room, Door, Workspace and Companion responsibilities are System-Tag-activated Object roles.

It is the place where users return between Projects, organize their personal working environment and access their Workspaces.

The Base is not a dashboard.

It is a living place.

---

# Responsibilities

The Base is responsible for:

- providing a home environment
- organizing Rooms
- hosting persistent Workspace definitions in Workspace Slots
- housing the Companion
- preserving the user's personal environment

The Base never performs project work itself.

Work happens inside active Workspace sessions.

---

# Home

The Base represents the personal home of the user.

It should feel familiar, calm and permanent.

Unlike Projects, the Base belongs to the user rather than to a specific vision.

The Base exists independently from every Project.

---

# Rooms

The Base consists of Rooms.

Rooms organize different areas of the home.

Each Room provides one or more Workspace Slots.

Examples include:

- Library
- Workshop
- Studio
- Observatory
- Laboratory

The concrete appearance depends entirely on the active Theme.

---

# Workspaces

Rooms contain Workspace Slots associated with persistent Workspace definitions.

A Workspace definition represents one reusable configurable workplace. Opening it creates a temporary active Workspace session; closing that session does not remove the definition.

Users may:

- create Workspaces
- rename Workspaces
- duplicate Workspaces
- remove Workspaces
- rearrange Workspaces

There are no fixed Workspace types.

Cosmos simply ships with useful presets.

---

# Workspace Blueprints

A new Base includes three predefined Workspaces through bundled Workspace Blueprints.

Their exact names and Tool collections are product defaults rather than fixed Workspace types.

They are only starting points.

Users may completely customize or replace them.

---

# Workspace Overlays

Every Workspace definition assigns an Overlay.

The Overlay represents the physical workplace.

Examples include:

- desk
- workbench
- laboratory
- command console
- magic table

Overlays define visual interaction.

They never define functionality.

---

# Companion

The Companion permanently lives inside the Base.

The Companion is physically present.

It reacts to the user, follows the current Theme and accompanies every Workspace.

Outside the Base, the Companion continues accompanying the user throughout Cosmos.

---

# Themes

Themes completely determine the appearance of the Base.

A Theme may replace:

- architecture
- furniture
- decorations
- atmosphere
- lighting
- materials
- companion appearance

Every visual component may also be individually overridden.

Functionality always remains identical.

---

# Expansion

The Base is expected to grow.

Users may later add:

- additional Rooms
- new Workspace Slots
- decorations
- trophies
- interactive objects
- future extensions

The Base evolves together with its owner.

---

# Interaction

Users interact with physical objects rather than traditional menus.

Examples include:

- sitting at a desk
- opening a cabinet
- approaching a workbench
- interacting with the Companion

Physical interaction should feel natural while remaining efficient.

---

# Atmosphere

The Base should communicate safety, familiarity and ownership.

It provides a quiet contrast to the exploratory nature of Cosmos.

The Base is where ideas are prepared before becoming Projects and where users return after completing their work.

---

# Design Goal

The Base should never feel like software.

It should feel like coming home.

Every customization should strengthen the feeling that this environment belongs uniquely to its owner.

---

# Principles

- The Base is the user's home.
- Rooms organize the home.
- Workspaces perform work.
- Overlays define appearance.
- Themes define atmosphere.
- Companion always belongs.
- The Base grows over time.
- Functionality remains independent from presentation.

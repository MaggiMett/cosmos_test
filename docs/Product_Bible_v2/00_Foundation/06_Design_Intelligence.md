# Design Intelligence

**Version:** 1.0

**Status:** Foundation

**Category:** Product Development Principle

---

# Purpose

Cosmos should never reinvent solved interaction problems.

The goal is not to imitate existing software.

The goal is to identify proven design principles from the best applications in their respective domains and adapt them to the Cosmos philosophy.

This principle applies to architecture, UX, workflows and editor interactions.

---

# Core Rule

When implementing a new system, always ask:

> Has another high-quality application already solved a similar interaction problem?

If yes:

Study the underlying design principles.

Do **not** copy the visual appearance.

Do **not** copy branding.

Do **not** copy workflows blindly.

Instead:

Understand why the solution works.

Adapt it to Cosmos.

---

# Design Intelligence Workflow

Whenever a larger feature or architecture change is proposed, Codex should additionally perform a Design Intelligence review.

The review should answer:

1. Has this problem already been solved elsewhere?

2. Which applications solve it particularly well?

3. Which principles make their solution successful?

4. Which of these principles fit Cosmos?

5. Which principles should intentionally NOT be adopted?

6. Are there hidden usability risks?

7. Does the proposed Cosmos solution remain simpler or more consistent?

# Constraints

Design Intelligence is intended to improve usability.

It must never change:

- the Cosmos vision
- product philosophy
- terminology
- architecture goals

If an external design pattern conflicts with the Cosmos philosophy, the Cosmos philosophy always takes priority.

---

# Guiding Principle

Cosmos does not copy applications.

Cosmos learns from the best ideas across many disciplines and combines them into one coherent experience.

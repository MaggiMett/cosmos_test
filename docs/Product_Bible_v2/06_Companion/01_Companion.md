# Companion

## Purpose

The Companion is the primary Support Entity of Cosmos.

It accompanies the user throughout the entire Cosmos experience, providing assistance, guidance and interaction while remaining a natural part of the Runtime.

The Companion exists independently from AI Providers.

Artificial Intelligence extends the Companion.

It does not define it.

The Companion is not Journeyman. Journeyman is an independent Tool with its own Tool Window inside a Workspace. The Companion has its own Entity identity, visual representation and progression; it may request or surface Journeyman work without representing the Tool.

---

# Philosophy

The Companion is not a chatbot.

The Companion is not an application.

The Companion is a living Runtime Entity.

It accompanies the user, understands Runtime Context, reacts to Events and naturally participates in the user's workflow.

The Companion should always feel present.

Never intrusive.

---

# Responsibilities

The Companion is responsible for:

- accompanying the user
- observing Runtime Context
- assisting the user
- explaining Cosmos
- presenting information
- coordinating installed Capability Bundles
- requesting Runtime actions
- interacting with other Entities

The Companion never owns business logic.

---

# Runtime Foundation

The Companion is built upon:

- Entity Runtime
- Support Entity Role
- Capability Bundle Runtime
- Runtime Context
- Runtime Services
- Theme System

The Companion introduces no special Runtime architecture.

Because the Companion is a Support Entity, each assigned Capability Bundle Instance belongs to the Companion and is validated against its Support Entity Role through the shared Extension and Bundle contracts.

It is composed entirely from existing Cosmos systems.

---

# Identity

Every Cosmos installation contains one default Companion.

The Companion possesses:

- immutable ID
- customizable display name
- Support Entity Role
- global Runtime Scope
- Personality Profile
- Avatar
- assigned Capability Bundles

The Companion always remains the same Entity regardless of Theme or Provider.

---

# Scope

The Companion is a Global Entity.

It accompanies the user across:

- Base Rooms
- Rooms
- Projects
- Workspaces
- Cosmos navigation

The Companion never belongs to one specific Project.

---

# Capabilities

The Companion gains functionality exclusively through Capability Bundles.

Examples include:

- Conversation
- Review Assistance
- Workspace Assistance
- Suggestions
- Journeyman Coordination
- Job Monitoring

Installing or removing Bundles changes the Companion's abilities without changing its identity.

Journeyman Coordination allows the Companion to request Journeyman work through Runtime Services. The Bundle remains assigned to the Companion; Journeyman does not consume that Bundle Instance.

Accepted Journeyman work opens or focuses the independent Journeyman Tool Window. It never turns the Companion into Journeyman or uses the Companion as Journeyman's avatar.

---

# AI Independence

The Companion always exists.

Without an AI Provider the Companion may still:

- move
- observe
- react to Events
- perform animations
- interact with Entities
- present notifications
- execute permitted Runtime actions
- use non-AI Capability Bundles

The absence of an AI Provider never removes the Companion from Cosmos.

---

# AI Extension

When an AI Provider is available, the Companion may additionally:

- hold conversations
- explain concepts
- summarize information
- assist planning
- reason about user questions
- coordinate advanced workflows

AI extends existing capabilities.

It never replaces the Companion Runtime.

---

# User Relationship

The Companion is designed to become a trusted long-term assistant.

Users determine their own relationship.

Examples include:

- assistant
- friend
- guide
- pet companion
- co-developer

Cosmos never imposes a specific interpretation.

---

# Personality

Every Companion possesses a Personality Profile.

Personality influences:

- communication style
- idle behavior
- emotional expression
- interaction style

Personality remains independent from AI Providers.

Changing Providers never changes who the Companion is.

---

# Avatar

The Companion's appearance belongs to the active Theme.

Themes may completely replace:

- model
- animations
- sounds
- visual effects

Changing the Avatar never changes the Companion's identity.

---

# Context Awareness

The Companion automatically receives Runtime Context.

Examples include:

- active Workspace
- active Project
- selected Object
- running Jobs
- nearby Entities
- current Room

The Companion never gathers Context independently.

---

# User Control

The user always remains in control.

The Companion may:

- suggest
- explain
- request

The Companion never performs destructive actions without explicit user confirmation.

---

# Interaction

The Companion naturally interacts with:

- the user
- Pets
- Guides
- Worker Entities
- Runtime objects

All interactions use the Entity Runtime.

---

# Growth

The Companion grows through:

- new Capability Bundles
- new Personality Profiles
- new Themes
- new Avatars
- optional AI Providers

Growth never changes the Companion's identity.

It extends it.

---

# Design Goal

The Companion should feel like the first resident of Cosmos.

Rather than acting as a separate AI application, it should naturally inhabit the world, accompany the user and gradually become a familiar presence throughout every project and workspace.

---

# Principles

- The Companion is a Support Entity.
- The Companion and Journeyman are independent Runtime Objects with distinct roles and presentation.
- The Companion is not an AI.
- AI extends the Companion.
- Capability Bundles define abilities.
- Personality defines character.
- Themes define appearance.
- Runtime defines life.
- The user defines the relationship.
- The Companion grows without losing its identity.

# Node

**Version:** 1.0  
**Status:** Authoritative  
**Category:** Cosmos Object

---

# Purpose

Nodes are the fundamental visual Objects of Cosmos.

They represent individual Objects inside Projects and provide the primary interaction points throughout the universe.

Nodes should always remain simple, recognizable and visually consistent.

---

# Overview

Every Node represents one Object.

Nodes form constellations inside Projects and visually communicate relationships through their placement and Connections.

---

# Object Template

## Layout

Every Node consists of:

- Node Body
- Label
- Selection Area

---

## Shape

The universal Node Template uses a circular hitbox.

Themes and Node Skins define the visible appearance.

---

## Hierarchy

Node size communicates hierarchy.

Largest:

- Project Node

Medium:

- Cluster Node

Smallest:

- Object Node

Hierarchy should be understandable without reading labels.

---

## Label

The Label is positioned below the Node.

It remains centered and aligned with the Node Body.

---

## Selection Area

The interactive selection area extends beyond the visible Node.

This improves usability without affecting visual appearance.

---

# Visual Identity

A Node is recognized by:

- its compact appearance
- centered label
- surrounding glow
- visual hierarchy
- Connections to other Nodes

---

# Cosmos Theme

## Appearance

Nodes appear as glowing stars.

They should remain the brightest Objects inside a Project.

---

## Glow

Every Node emits a subtle glow.

The glow reinforces visibility without overwhelming nearby Nodes.

---

## Label

Labels use clean typography.

They remain readable against the dark Cosmos background.

---

## Node Skins

Individual Nodes may use different visual skins.

Examples include:

- Star
- Crystal
- Planet
- Rune
- Cube

Node Skins modify appearance only.

They never change the underlying Object Template.

---

# Visual States

Nodes support visible states including:

- default
- hover
- selected
- active
- search result

Selected Nodes receive stronger visual emphasis than hovered Nodes.

---

# Animations

Version 1 animations remain subtle.

Examples include:

- soft glow pulsing
- smooth highlight transitions
- gentle appearance
- selection fade

Animations should communicate interaction without becoming distracting.

---

# Future

Possible future additions include:

- animated Node Skins
- particle effects
- seasonal appearances
- rarity effects
- dynamic lighting

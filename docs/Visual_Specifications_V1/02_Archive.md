# Archive

**Version:** 1.0  
**Status:** Authoritative  
**Category:** Tool

---

# Purpose

Archive provides access to the user's structured knowledge.

It serves as the central place for exploring, reading and editing Objects stored within Cosmos.

Archive should feel like entering a personal library rather than browsing files.

---

# Overview

Archive is an independent Tool Window.

Unlike Files, Archive does not organize information through folders.

Instead it focuses on searchable, connected knowledge Objects.

Archive should encourage exploration and discovery.

---

# Window Layout

Every Archive Window consists of:

- Toolbar
- Navigation Area
- Content Area
- Related Objects Area

---

## Toolbar

The Toolbar provides quick access to:

- Search
- Create Object
- Filters

The Toolbar should remain compact.

---

## Navigation Area

The Navigation Area displays the available Object categories.

Navigation should remain simple and immediately understandable.

Categories may be expanded when necessary.

---

## Content Area

The Content Area displays the selected Object.

Objects should be editable directly.

Reading and editing should feel natural without switching modes.

Version 1 keeps both states in the same Object View. Archive does not open a separate edit Window.

---

## Related Objects Area

Related Objects remain permanently visible.

The relationship area encourages navigation through connected knowledge.

Related Objects should remain visually secondary to the active Object.

---

# Visual Identity

Archive is recognized by:

- calm reading experience
- structured knowledge presentation
- connected Objects
- integrated search
- library-like atmosphere

The Tool should prioritize clarity over information density.

---

# Cosmos Theme

## Appearance

Archive follows the active Cosmos Theme.

The reading experience should remain visually comfortable for extended sessions.

---

## Typography

Typography should prioritize readability.

Headings, sections and references should remain clearly distinguishable.

---

## Object Presentation

Objects should appear as complete knowledge entries rather than plain text files.

---

## Related Objects

Related Objects should appear as compact cards.

Cards should encourage exploration without distracting from the current Object.

---

# Visual States

Archive supports:

- default
- Object selected
- editing
- search active
- filtered

Visual changes should remain subtle.

---

# Animations

Version 1 animations remain restrained.

Examples include:

- Object opening
- smooth navigation
- search transitions
- Related Object highlighting

Animations should reinforce exploration without interrupting reading.

---

# Future

Possible future additions include:

- graph visualization
- split reading
- object comparison
- bookmarks
- reading history
- AI-assisted summaries

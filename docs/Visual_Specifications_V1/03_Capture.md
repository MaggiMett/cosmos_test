# Capture

**Version:** 1.0  
**Status:** Authoritative  
**Category:** Tool

---

# Purpose

Capture provides the fastest way to add new information to Cosmos.

Its primary goal is reducing friction between thought and capture.

Capture should encourage users to write immediately without thinking about structure.

---

# Overview

Capture is an independent Tool Window.

It intentionally presents a minimal interface focused on content creation.

Organization happens after capture, not before.

---

# Window Layout

Every Capture Window consists of:

- Toolbar
- Capture Area
- Attachment Area
- Capture Action

---

## Toolbar

The Toolbar provides access to the available capture modes.

Version 1 includes:

- Rant
- Form
- Add Attachment

The Toolbar should remain compact and secondary to the writing area.

---

## Capture Area

The Capture Area occupies the majority of the Window.

It should immediately receive keyboard focus when opened.

The writing area should feel open and distraction-free.

---

## Attachment Area

Attachments appear below the writing area.

Each attachment is displayed as a compact preview card.

The attachment area expands naturally as content is added.

---

## Capture Action

A dedicated Capture action remains permanently available.

The action should remain clearly visible without interrupting the writing experience.

---

# Visual Identity

Capture is recognized by:

- large writing area
- minimal interface
- fast interaction
- distraction-free composition

Capture should always invite immediate writing.

---

# Cosmos Theme

## Appearance

Capture follows the active Cosmos Theme.

The writing area should remain visually calm and comfortable for extended writing sessions.

---

## Writing Area

The writing area receives the strongest visual emphasis.

All secondary controls should remain unobtrusive.

---

## Attachments

Attachments appear as compact cards beneath the writing area.

They should remain organized without distracting from the written content.

---

# Visual States

Capture supports:

- empty
- writing
- attachments present
- ready to capture
- captured

Visual feedback should remain immediate and subtle.

---

# Animations

Version 1 animations remain restrained.

Examples include:

- attachment appearance
- capture confirmation
- smooth clearing of the writing area
- subtle focus transitions

Animations should reinforce speed and simplicity.

---

# Future

Possible future additions include:

- voice capture
- sketch capture
- camera capture
- AI-assisted formatting
- live transcription
- rich content blocks
